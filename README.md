# Steam Activation v3.2 Wrapper

Локальное приложение для моделирования **паровой активации растительных карбонизатов** на базе сохранённой исходной версии решателя v3.2.

## 1) Назначение проекта

Проект предоставляет:
- программный API (`solve_activation`) для одиночных и серийных расчётов;
- Streamlit-интерфейс для работы со сценариями;
- параметрический анализ и поиск рационального режима;
- экспорт PNG/CSV/TXT/DOCX и материалы для раздела 4.5 диссертации.

## 2) Структура проекта

- `2.5f_revised_v3_2 (1) (1).py` — **legacy-скрипт, исходная рабочая версия v3.2 (сохранён, не удалять)**.
- `activation_core.py` — ядро-обёртка и `solve_activation`.
- `activation_params.py` — параметры по умолчанию и 7 видов сырья.
- `activation_validation.py` — физическая валидация и классификация режима.
- `activation_parametric.py` — серии расчётов и оптимизация.
- `activation_plots.py` — графики и PNG-экспорт.
- `activation_report.py` — TXT/DOCX/CSV/диссертационный экспорт.
- `app.py` — Streamlit-приложение.
- `test_activation_smoke.py` — локальный smoke-test физической эквивалентности.
- `test_imports.py` — минимальная проверка импортов.
- `examples/default_sunflower_husk.json` — пример сценария.
- `docs/local_checklist.md` — локальный чек-лист.
- `outputs/` — каталог экспортов.

## 3) Установка (Windows)

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## 4) Запуск smoke-test

```bash
python test_activation_smoke.py
```

Smoke-test:
- печатает фактические значения;
- печатает контрольные значения v3.2;
- проверяет допуски:
  - `X_mean ±7%`
  - `Y_AU ±7%`
  - `S_BET ±10%`
  - `gas_residual <= 10%`
- коды завершения:
  - `0` — успех;
  - `1` — численное несовпадение;
  - `2` — отсутствуют зависимости.

## 5) Запуск приложения

```bash
streamlit run app.py
```

## 6) Запуск legacy-скрипта

```bash
python "2.5f_revised_v3_2 (1) (1).py"
```

Для legacy-режима нужен `config.json` требуемого формата.

## 7) Работа со сценариями JSON

- В sidebar: загрузка и сохранение сценария JSON.
- Во вкладке «Экспорт и отчёт»: отдельные кнопки для сохранения/загрузки сценария.
- Готовый пример: `examples/default_sunflower_husk.json`.

## 8) Сохранение отчётов и экспортов

Вкладка «Экспорт и отчёт» позволяет сохранить:
- `results` в JSON;
- таблицы CSV;
- TXT-отчёт;
- DOCX-отчёт (если установлен `python-docx`);
- материалы «Диссертационный экспорт» (PNG 300 dpi, TXT/DOCX 4.5, captions/interpretation).

## 9) Если зависимости не устанавливаются

В облачной среде Codex установка может падать из-за proxy 403.

Рекомендация:
1. Выполнять runtime-проверки локально.
2. В облаке ограничиться `py_compile`.

## 10) Контрольные значения v3.2

- `X_mean ≈ 33.45 %`
- `Y_AU ≈ 66.55 %`
- `S_BET ≈ 838 м²/г`
- `gas_residual ≈ 6.5 %`

## 11) Важное предупреждение

**Численные результаты после рефакторинга должны быть подтверждены локальным smoke-test; в Codex Cloud runtime-проверка может быть недоступна из-за proxy 403.**

## 12) Что является предварительным

- параметры 7 видов сырья;
- инженерные индексы;
- оптимизация;
- диссертационные подписи и интерпретации.

Все эти элементы требуют экспериментальной калибровки.

## 13) Что нельзя менять без согласования

- физическую модель;
- кинетику;
- RPM;
- тепловой баланс;
- газовый баланс.

## 14) Параметрический анализ и оптимизация

Доступны серии по:
- температуре пара;
- расходу пара;
- размеру частиц;
- плотности гранул;
- сравнению 7 видов сырья.

Оптимизация использует интегральный `score` с ограничениями по `S_BET`, `Y_AU`, `X`, `gas_residual`, температуре и предупреждениям.

## 15) Экспорт материалов для диссертации

В блоке «Диссертационный экспорт»:
- PNG 300 dpi;
- DOCX/TXT для раздела 4.5;
- CSV-таблицы (критерии, сравнение сырья, рациональные режимы, optimization top-10);
- captions и интерпретации в TXT/MD.

> Подписи и интерпретации — черновики. Предварительные/литературные данные нужно заменить экспериментальными.
